# 结果预览稀疏化

## 实现

结果 BlueMap 不再直接读取正式输出，而是读取 `viewers/result-sparse-<key>/world` 中的固定副本。首次检查主世界区域，保留实际内容和一圈已存在的邻区；正式输出、原地图均不修改。

该副本保持固定路径和区块时间戳。区域内容未变时，文件指纹检查直接复用副本；`level.dat` 独立同步，不因转换器重写元数据而重新扫描整图。内容变化时只重写受影响的副本区域，不变的远处区块保持预览时间戳。

副本保留曾参与预览的区块：它们变为空气或整个源区域被移除时，写入有新时间戳的空气记录。这样 BlueMap 会清空旧模型，不会因“空区块被过滤”留下残影。相邻一圈区块同步标记，确保连接、光照、遮挡及时更新。此规则只保留预览涉及过的范围，不把历史远方空区块引入副本。

首次渲染、转换后的增量渲染和手动重新渲染使用同一准备入口。前端报告仍指向正式输出路径。旧预览使用另一个缓存目录，不混用瓦片；迁移时复用旧目录的 Minecraft 客户端资源与资源扩展，避免重复下载。

## 验证（2026-09-16）

实际 `aa_1.12.2` 输出含 24 个区域文件、16,565 条区块记录，其中实际内容 367 个。新副本为 4 个区域、469 个区块（含 102 个邻区），跳过 16,096 条空白记录。

在已有客户端贴图、本机同样的 2 线程／2 GB BlueMap 限制下：

| 场景 | 副本准备 | 渲染进程 |
|---|---:|---:|
| 真实地图首次完整渲染 | 2.49 秒 | 7.60 秒 |
| 无变化再次渲染 | 0.01 秒 | 1.82 秒 |

后续重复实测约 2 秒。耗时不含首次联网下载贴图与浏览器加载时间，其他机器／地图会有差异。

- 正式输出逐文件 SHA-256 未变化。
- 无变化时全部远近模型文件指纹未变化；渲染状态文件 `.rstate` 正常更新，不计为瓦片改写。
- 使用真实 BlueMap 运行方块体 → 修改材质 → 删除整个区域：排除随机 UUID 后网格材质确实改变，删除后高清网格顶点数为零。
- 单元测试覆盖固定路径复用、空区块过滤、整区域删除、跨区域近邻刷新、远处时间戳不变、元数据独立更新。
- 生命周期测试覆盖首次、增量和手动刷新都使用稀疏副本，正式输出路径保持原义，以及旧贴图缓存迁移。
- 完整 Java 测试与前端刷新状态机测试通过；进度提示和资源迁移调整后再次通过相关定向测试。

## 复跑真实渲染测试

`tools/tests/VerifySparseResults.java` 使用真实 BlueMap，在独立测试目录验证上述流程。它只读第一个参数的世界，仅修改第二个参数下的合成用例。

用 Java 21 对主程序 jar 编译该文件（`javac -encoding UTF-8 -cp <主程序jar> -d <测试classes目录> tools/tests/VerifySparseResults.java`），运行类 `com.hivemc.chunker.web.VerifySparseResults`，参数依次为：正式输出路径、独立测试目录、BlueMap 安装目录、Java 可执行文件。可将已缓存的 `minecraft-client-1.12.0.jar` 与 `resourceExtensions.zip` 复制到测试目录的 `real/data/`，排除网络下载时间。
