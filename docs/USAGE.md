# 使用说明

## 运行

解压后双击 `启动.bat`。浏览器会自动打开界面（默认 `http://localhost:8123/`）。

关闭那个命令行窗口就是退出。

如果 8123 被占用，程序会自动换到 8124、8125……具体端口在窗口里会写出来。

## 选地图

三种方式都行：

1. **自动查找**：点「自动查找我电脑上的存档」，会扫常见位置（包括各种启动器的
   `.minecraft/versions/*/saves/`），列出找到的地图，点一下即选中。
2. **弹选择框**：点「选择文件夹…」，在弹出的系统选择框里定位到存档文件夹。
3. **直接填路径**：把路径粘进输入框。带不带引号都行，`file://` 前缀会自动去掉。

要选的是**存档文件夹本身**（里面能直接看到 `level.dat`、`region`），不是它的上一级。
选错时程序会提示，不会糊里糊涂地失败。

> 拖拽为什么不能用：浏览器的安全规则决定了网页拿不到拖入文件夹的真实路径，
> 只能看到文件夹名字。所以拖入后会自动弹出系统选择框，这是唯一能拿到真实路径的方式。

## 转换

### 先看看会丢什么（推荐）

点「先分析会丢失什么」，几秒内告诉你：

- 这张图里有多少方块会**彻底丢失**（变成空气）
- 有多少会被**换成别的方块**，换成了什么、各多少数量

**不会修改原存档或生成正式转换结果**。它同时会把清单填到下方的映射表里。

网页分析会建立独立的稀疏输入缓存并执行临时试转，不修改原存档，也不生成正式转换结果。
内容核查同时供源地图预览和后续转换使用：跳过远处全空区块，保留内容区块周围一圈上下文。
保留与跳过数量会出现在转换报告中。自然地形也会保留，程序不会凭玩家停留时间猜测哪里有人造建筑。

### 两个选项

- **自动上移地图**（默认开）：1.18 及以上的存档延伸到 Y=-64，而 1.12.2 只能到 0~255。
  勾选后整张地图上移，使最低方块落在 Y=0。1.13~1.17 的存档本来就在范围内，不会被挪动。
- **把 1.12.2 没有的方块换成最接近的**（默认开）：关闭后这些方块直接变空气。

### 方块映射（可选）

上半部分列出**你这张图**里实际会丢或被换的方块，按数量从多到少排序，每条都能改。
你写的规则**优先于内置规则**。

下半部分（默认折叠）是内置的 275 条通用规则，与你的地图无关，只在你确实想改某一类时才需要看。
带搜索框，输 `stairs` 就能筛出所有楼梯相关的规则。

两边都带方块图标，直接看得出「什么换成了什么」。

### 开始转换

点「开始转换」。完成后：

- 下方出现**转换报告**
- 右侧**自动**开始渲染左右对比（不用手动点刷新）

## 左右对比预览

左边是源地图，右边是 1.12.2 的转换结果，各是一个独立的 3D 查看器。

首次渲染要下载对应版本的 Minecraft 贴图，**需要联网**，之后会缓存。
真实存档渲染要几分钟，状态栏会显示进行到哪一步和已经用了多少秒。
左边渲完就会先出现，不用等右边。

只执行分析也会独立生成源预览；点击「查看源地图」即可打开。页面会显示下载贴图、加载资源、
渲染进度和已用时间。首次镜头会定位到内容范围，隐藏的预览面板不会提前初始化 WebGL 画布。

同样设置重复转换时，未变化区块不会重写。如果把旧建筑映射成空气，会写入清空结果，
避免由于跳过空白而留下旧建筑。筛选缓存位于工具的 `work/sources/` 下，源地图变更后重新核查。

### 改映射后实时生效

这是这个工具比较特别的一点：

1. 改一条映射
2. 点「开始转换」
3. 右侧预览**自己更新**（几秒到几十秒），不用手动刷新

完成顺序是「转换写盘 → 增量渲染 → 当前视野瓦片加载完成」。这三个阶段都会等待结束，
不会在新瓦片尚未生成时把旧画面标为完成。渲染失败会明确提示，原转换结果仍保存在磁盘。
升级后首次遇到旧缓存会自动完整修复一次，后续使用增量渲染；无需另外点击「重新渲染预览」。

原理：重新转换时，内容没变的区块**根本不写盘**，只有真正变了的区块会被重写并打上新时间戳；
预览服务按每个区块自己的时间戳判断该重渲哪些，只重渲那一小部分。

报告里会写明「重新写入的区块: N 个（其余 M 个与上次完全相同，未重写）」，
你能直接看到到底动了多少。

## 转换报告

输出文件夹里有 `conversion-report.json` 和 `conversion-report.txt`，界面下方也会显示。

报告回答的问题是「**你到底对我的地图做了什么**」：

| 字段 | 含义 |
|---|---|
| `versions` | 源版本与目标版本 |
| `shift` | 上移了多少格、最低/最高方块 Y、裁掉了多少 |
| `blocks` | 方块总数、种类数、按数量排序的清单 |
| `unmapped` | 完全丢失的方块（种类 + **实例数** + 按数量排序的前几名） |
| `substitutions` | 被换成别的方块的清单（原方块 → 新方块 + 数量） |
| `removed` | 删了多少实体、清了多少容器物品 |
| `changed` | 本次重写了多少区块、多少没变 |

**为什么报告很重要**：转换本身不会告诉你哪里少了东西。报告是唯一能分辨
「本来就没有」和「转换丢了」的依据。

## 转换规则（刻意的取舍）

这个工具是为了**搬运建筑外观**，不是完整复制世界：

| 内容 | 处理 |
|---|---|
| 生物、掉落物、盔甲架等实体 | 删除 |
| **画与展示框** | **保留**（它们是建筑的一部分），发光展示框转普通展示框 |
| 箱子等容器 | 保留方块外观，**内部物品清空** |
| 1.12.2 没有的方块 | 换成最接近的（可在界面上改），实在无可替代的变空气 |
| 超出高度上限的部分 | 裁掉，并计入报告 |
| 红石行为、命令方块内容 | 不降级 |

## 命令行用法

不想开界面时：

```
java -jar chunker-cli-1.20.0.jar cli -i <源地图> -o <输出> -f JAVA_1_12_2 --shiftToFit
```

常用参数：

| 参数 | 作用 |
|---|---|
| `-i, --inputDirectory` | 源地图 |
| `-o, --outputDirectory` | 输出目录 |
| `-f, --outputFormat` | 目标格式，用 `JAVA_1_12_2` |
| `-m, --blockMappings` | 自定义映射的 JSON 文件 |
| `--shiftToFit` | 上移使最低方块落在 Y=0 |
| `--noApproximations` | 关掉近似替换（不换，直接变空气） |

**注意**：不加 `cli` 子命令会启动**网页界面**（这是设计如此）。脚本里调用时别忘了加。

## 常见问题

**提示「这个文件夹里没有 level.dat」**
选到存档文件夹本身，不是上一级，也不是 `saves` 目录。

**右侧预览是黑的**
确认已经渲染完（状态栏会写完成）。另外确保程序**没有在 8123 端口被旧实例占着**——
如果你开了多个窗口，新实例会退到 8124，而浏览器里看的可能是旧的。先全部关掉再重开。

**首次渲染报错或很慢**
首次需要联网下载 Minecraft 贴图。下载失败会在状态栏写明原因。

**转换后地图看起来空了一半**
打开报告看 `shift` 和 `unmapped`。常见原因是建筑建在 Y=256 以上被裁掉了（1.18+ 世界高达 320），
这在报告里会写明裁了多少。
